# СНО КГУ — старт в науку

Адаптивное серверное приложение: Laravel 12, PHP 8.4, Blade, PostgreSQL 17, обычные CSS и JavaScript. Авторизация — сессионная; интерфейс, запросы и содержимое на русском языке. Это работающая первая версия, а не имитация кабинетов в браузере.

## Запуск

Нужны Docker Engine и Compose v2. На Linux рабочая копия должна быть доступна пользователю контейнера (по умолчанию UID/GID 1000; переопределяются `LOCAL_UID`/`LOCAL_GID`).

```bash
./scripts/setup.sh
```

Скрипт собирает PHP-образ, устанавливает зависимости по `composer.lock`, создаёт `.env` только при отсутствии, генерирует ключ только если он пуст, запускает PostgreSQL, применяет миграции и добавляет демонстрационные записи. Существующие данные не очищаются. `DemoSeeder` повторяем и запрещён в production.

Порт приложения — **8000**. Корень сайта — `public/`. CSS, шрифты и JavaScript находятся в `public/`; npm/Vite для запуска не нужны. В облачной среде скрипт использует предоставленные proxy-переменные и доверенный CA-файл, если они есть. Проверки TLS и подписей пакетов включены. После установки:

```bash
./scripts/start.sh              # запуск сохранённых контейнеров
./scripts/test.sh               # PHPUnit, отдельная БД snokgu_test
docker compose logs -f app     # журнал приложения
docker compose stop           # остановка с сохранением данных
```

PostgreSQL хранит данные в named volume `snokgu_postgres-data`; удаление тома удалит данные. Он не опубликован на порту хоста. Для резервной копии используйте `docker compose exec -T db pg_dump -U snokgu snokgu > backup.sql` и храните её безопасно вне Git. Не рассчитывайте на перенос Docker volume между разными облачными машинами: на новой машине setup создаёт базу из миграций и демо-данных.

Если PHP уже установлен: PHP ≥8.4 с `pdo_pgsql`, `mbstring`, `dom`, `xml`, `xmlwriter`, `curl`, `zip`, `bcmath`; Composer 2; PostgreSQL 17. Выполните `composer install`, скопируйте `.env.example` в `.env`, укажите PostgreSQL, выполните `php artisan key:generate`, `php artisan migrate --seed` и `php artisan serve --port=8000`. Перед тестами создайте отдельную базу `snokgu_test` с тем же владельцем. `tests/TestCase.php` принудительно выбирает её, не наследуя имя рабочей базы.

Проверено на PHP **8.4.26**, Laravel **12.70.0**, Composer **2.10.3**, PostgreSQL **17.11**. В lock-файле архивы GitHub используют официальный `codeload.github.com` вместо API-переадресации, недоступной через текущую сетевую политику. Версии, refs и контрольные суммы пакетов не подменялись.

## Демо-доступ

Для локальной среды пароль всех пяти аккаунтов: **`demo-local-only-2026`** (переменная `DEMO_PASSWORD` задаёт пароль только при первом создании демо-пользователя).

| Роль | Почта |
|---|---|
| Студент | `student@example.test` |
| Наставник цифровых задач | `mentor@example.test` |
| Наставник социальных задач | `social@example.test` |
| Наставник естественных наук | `nature@example.test` |
| Организатор | `organizer@example.test` |

Все задачи, профили и мероприятия из seed помечены как примеры. Названия подразделений и учебные записи не являются официальными сведениями КГУ. Настоящие имена сотрудников, контакты, достижения и новости не выдуманы: соответствующие блоки пусты. Новые аккаунты регистрируются только как студенты. Организатор может создать профиль наставника для зарегистрированного пользователя. Нового организатора назначает администратор сервера; публичной формы повышения прав нет.

## Что работает

- Публичные главная, «О СНО», FAQ, каталог задач, подбор по направлению/опыту/нагрузке с объяснением, поиск и пагинация, карточки задач и наставников.
- Подача заявки и своей идеи в общую очередь; назначение наставника организатором; согласование наставником; история решений, уточнения, отзыв и отказ с объяснением.
- Автоматическое создание исследования и первого этапа после принятия. Участники, этапы и сроки, отправка этапа на проверку, научное подтверждение наставником, комментарии и материалы-ссылки.
- Запрос помощи/паузы координатору, ответ в кабинете, сохранение истории и согласованное возобновление.
- Мероприятия: список и календарь с выбором месяца, запись, подтверждение, отмена, защита от повторов и ограничения мест. Закрытая ссылка доступна только записавшимся. После встречи организатор может обновить её ссылкой на материалы.
- База знаний с поиском, категориями и полноценными примерами статей; скачивание универсальных Markdown-шаблонов плана, презентации и отчёта. Они не объявлены официальными стандартами КГУ.
- Три кабинета; наставник редактирует свои задачи и доступность; организатор управляет задачами, профилями, подразделениями, мероприятиями, статьями, FAQ, новостями, документами и контактами. Снять публикацию/закрыть набор можно без удаления истории.
- Внутренние уведомления, отдельный учёт времени наставника, статистика новичков, принятых участников, первого ответа, первого этапа, завершений и состояний рукописей.
- Отдельная публикация результата: согласие **каждого** участника, завершённое исследование и явное действие организатора с отдельным публичным текстом. Отзыв согласия скрывает карточку. Рабочие материалы, заявки и комментарии не выводятся в публичную карточку.

Статистика принятых участников считает разных студентов в исследованиях; число принятых заявок выводится отдельно. Среднее время ответа — календарные часы до первого непустого ответа ответственного, без автоматических уведомлений. Целевой срок координатора не задан до согласования; организатор может указать его в настройках.

## Как пройти главный сценарий

1. Студент выбирает задачу, пишет о своём интересе и отправляет заявку. У выбранной задачи посмотрите, какой указан наставник.
2. Организатор открывает «Кабинет → Очередь заявок», назначает доступного наставника и пишет ответ.
3. Назначенный наставник открывает заявку и согласует участие. Один рабочий кабинет создаётся автоматически, даже при повторной обработке того же принятия.
4. Студент открывает исследование, добавляет материал и комментарий, отправляет первый этап на проверку.
5. Наставник обсуждает результат, подтверждает этап и при необходимости добавляет следующий. Завершить исследование можно только после всех этапов.

## Фирменные материалы и официальные сведения

- `resources/views/components/logo.blade.php` — отдельный компонент логотипа. Сейчас текст «СНО КГУ». Здесь можно подключить исходный файл утверждённого университетского знака. Иллюстрация `public/images/campus.svg` декоративная и не выдаётся за официальный логотип.
- `public/css/app.css`, блок `:root` — палитра, шрифты, базовые отступы, радиусы и тени. Синий акцент интерпретирован по предоставленной фотографии палитры; точные фирменные значения нужно заменить после получения кодов цветов.
- `public/fonts/` — локальный Manrope с кириллицей, лицензия OFL. Нет зависимости от Google Fonts и внешних изображений.
- `/manage/settings` — подтверждённые контакты, справочный текст и согласованный срок ответа.
- `/manage/contents` — официальные документы, FAQ, новости, знания; `/manage/mentors` — реальные профили; `/manage/departments` — согласованный справочник подразделений.

## Интеграции и публикация

SMTP, университетский SSO, выдача/восстановление университетских учётных записей и доменное размещение не настроены. Внутренние уведомления работают без SMTP. Почтовые уведомления бизнес-событий пока не реализованы; одной настройки SMTP для них недостаточно. Первый выпуск не включает встроенный мессенджер и загрузку исследовательских файлов — материалы хранятся ссылками.

Docker-конфигурация предназначена для разработки. Для публичного сервера нужны HTTPS, PHP-FPM с веб-сервером, production-переменные и собственные учётные данные PostgreSQL, `APP_DEBUG=false`, безопасные cookies, резервное копирование и официальные документы для регистрации. Демонстрационные аккаунты и текущая демонстрационная форма регистрации не должны использоваться для реальных персональных данных. Не запускайте demo seed в production. Приложение не опубликовано на внешнем домене; скриншоты показывают текущий работающий экземпляр.

Архитектура, маршруты и права описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
