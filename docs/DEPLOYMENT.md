# Размещение

## GitHub Pages: публичное превью

Адрес: **https://akitwra.github.io/SNOKSU/**. Исходники полного приложения находятся в этом же репозитории.

Workflow `.github/workflows/pages.yml` после push в `main` создаёт отдельную PostgreSQL-базу, применяет миграции и демонстрационный seed, экспортирует гостевые страницы и публикует только `dist-pages/`. В Settings → Pages источником должен быть **GitHub Actions**. Повторную публикацию можно запустить через Actions → Publish public preview to GitHub Pages → Run workflow.

В превью доступны страницы, поиск по примерам, фильтры, календарь и скачивание шаблонов. Личный кабинет и вход убраны из публичной навигации и Pages-экспорта. Формы вопросов доступны без регистрации; для их работы на Pages подключается Google Форма или собственный PHP-обработчик, см. [QUESTIONS.md](QUESTIONS.md). До подключения приёма кнопка отправки отключена. Исследовательские заявки и сохранение остальных данных требуют PHP-сервера. Серверный код, `.env`, пароли, закрытые ссылки и рабочие кабинеты не входят в артефакт. Экспорт разрешён только в local/testing, для демонстрационных записей. Не запускайте его на базе с реальными участниками.

Ручной экспорт после настройки отдельной демонстрационной базы:

```bash
php artisan society:export-pages --base-path=/SNOKSU
```

## Render: полное приложение

`render.yaml` описывает Docker web service и отдельную PostgreSQL 17. Аккаунт Render ещё нужен; конфигурация сама по себе не создаёт внешние ресурсы. Перед подтверждением проверьте текущие ограничения и стоимость планов Render. `free` в Blueprint предназначен для временной оценки: ограничения сна, срока хранения базы и резервного копирования нужно проверить в интерфейсе Render.

1. Создайте аккаунт Render, подключите GitHub и выберите **New → Blueprint** → `akitwra/SNOKSU`, ветка `main`.
2. Проверьте ресурсы из `render.yaml`. В защищённых полях укажите `INITIAL_ORGANIZER_NAME`, `INITIAL_ORGANIZER_EMAIL` и `INITIAL_ORGANIZER_PASSWORD`. Пароль должен содержать не менее 14 символов, буквы и цифры. Не добавляйте эти значения в Git или переписку.
3. Подтвердите создание ресурсов. Render соберёт `docker/Dockerfile.production`. При старте применяются миграции, создаётся первый организатор и кэшируется конфигурация. Демонстрационные записи и известные демо-пароли не создаются.
4. Откройте HTTPS-адрес сервиса, проверьте `/health` и войдите через `/login`. Из кабинета организатора можно заполнить справочники, задачи, события и статьи. Новые студенты регистрируются через обычную форму; организатор назначает наставников.

`DB_URL` передаётся приватным подключением из управляемой базы; `APP_KEY_SEED` генерируется Render и преобразуется в постоянный Laravel-ключ. Не меняйте его после начала эксплуатации. `APP_URL` берётся из `RENDER_EXTERNAL_URL`, cookies защищены HTTPS, отладка выключена. В production доверяются прокси Render; при переносе на другой сервер задайте `TRUSTED_PROXIES` для его сети.

Повторный запуск не сбрасывает пароль существующего организатора и не добавляет демо-данные. После успешного первого входа удалите три `INITIAL_ORGANIZER_*` значения из настроек сервиса. Храните резервные копии PostgreSQL отдельно; локальная файловая система web service не предназначена для постоянных пользовательских файлов. Материалы исследований сейчас сохраняются ссылками.

Для запуска без Render используйте тот же Dockerfile, PostgreSQL, `APP_KEY` либо постоянный `APP_KEY_SEED`, `APP_URL`, `DB_CONNECTION=pgsql`, `DB_URL` и начальные переменные организатора. Контейнер слушает `PORT` (по умолчанию 10000). HTTPS обеспечивает платформа или внешний reverse proxy.

Перед сбором реальных персональных данных нужны утверждённые университетом сведения и документы регистрации, резервное копирование и эксплуатационный регламент. SSO и почтовая доставка отдельно не настроены.
